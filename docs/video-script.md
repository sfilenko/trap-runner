# Сценарій відео — Trap Runner (≤ 2:00)

> Чернетка агента для Task 6.2 Step 1. Текст пише і читає людина, тож його слід переписати своїми словами.
> Темп ≈ 120 слів на хвилину: кожен відрізок має ≤ 55 слів тексту.
> Перевірка рубрики: у відео є продукт і те, як його будували агентно; довжина ≤ 2:00.
>
> **Що зроблено насправді (рішення людини):** відео без голосу, з підписами; зібрав агент (`docs/autonomy-log.md`, «Відхилення від плану», Task 6.2). Порядок сцен — як нижче; текст підписів скорочено. Кадри гри — записані людиною розв'язки, програні через справжні `step()` і `draw.ts`; сцену смерті дає ввід агента, і підпис це каже.

## Підготовка до запису

1. **Гра — записати наперед, окремим кліпом.** `pnpm dev` → браузер. Пройти всі 5 рівнів: екран «Перемога!» з'являється лише після рівня 5, а перейти одразу на потрібний рівень гра не дає. Потрібні кадри:
   - рівень 1: підлога зникає під ногами (пастка `t1`, біля x = 28), смерть, лічильник смертей росте; монета-приманка `c36_13` → шипи;
   - рівень 3: стрибок на ворога `e1` (патруль 10–18);
   - екран «Перемога!» з монетами і смертями.
2. **Термінал:** великий шрифт (≥ 18 pt), чисте вікно, робоча тека `D:\AITools\trap-runner`. `pnpm check` іде ≈ 30 с: записати наперед і змонтувати або показати лише хвіст виводу.
3. **Вкладки браузера:** `docs/evidence.md` на GitHub (розділ 2), `docs/autonomy-log.md` → «Впевнені помилки агента», `docs/loop-log.md`.
4. **Запис і монтаж:** OBS Studio або Clipchamp (є у Windows 11). Win + Alt + R (Xbox Game Bar) пише лише одне вікно — для перемикання між грою і терміналом не підходить.

## 0:00–0:25 · Гра

**На екрані:** кліп гри: рівень 1 — пастки, смерть; рівень 3 — стрибок на ворога; «Перемога!».

**Текст:**
> Trap Runner — браузерний платформер. Пастки як у Level Devil: підлога зникає під ногами, монета-приманка вмикає шипи. Вороги і монети — як у Маріо, ворога знищує стрибок зверху. Уся логіка гри — одна чиста функція `step`, тому кожне правило перевіряється тестом без браузера.

## 0:25–0:50 · Гейт і журнал дій

**На екрані:**
```
pnpm check
cat .agent-log/blocked.jsonl
pnpm agent:log | head -3
```
У виводі показати: `0 violations`, `Tests  87 passed (87)`, `validate-level: 5 levels, 0 failed`; рядок `"blocked":true,"by":"guard-core","rules":["no-math-random"]`.

**Текст:**
> Одна команда перевіряє все: типи, чистоту ядра, 87 тестів і проходження кожного рівня записаним розв'язком. Правило «у ядрі немає Math.random» записане в AGENTS.md, але це не лише текст: hook заблокував запис агента, ось рядок у журналі. Кожну дію агента пише журнал hook'ів.

**Застереження:** `pnpm agent:log` показує `33 proposed but not executed`, але справжній блок hook — лише один (`blocked.jsonl`). Решта — інструменти без події `PostToolUse` (`AskUserQuestion`, `Skill` тощо). Не називати 33 «заблокованими».

## 0:50–1:20 · Цикл і червоний → зелений

**На екрані:**
```
cat .agent-log/loops/2026-10-04T07-09-59-998Z-level-04.jsonl
git log --oneline --reverse cb86c1e^..9993693
```
Показати `"ok":true`, `"cost_usd":0.407…`, `"turns":15`; три коміти: пропозиція OpenSpec → `test(validation): red tests …` → `feat(validation): …`.

**Текст:**
> Рівні 4 і 5 зробив цикл: агент пише рівень, валідатор його перевіряє, помилки йдуть у наступну ітерацію, ліміт — долар на виклик. Обидва рівні пройшли з першої ітерації, по сорок центів. Спека — раніше за код: пропозиція OpenSpec, потім червоний тест, два падіння, і лише тоді код, який робить його зеленим.

**Текст:**
